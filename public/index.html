Placement Lab · a two-numbers lab

Partition to manage. Shard to scale. Replicate to survive.

The same 12 rows, arranged three ways. Count the dots — how many machines hold the data and how many rows get stored tell you which technique does what.

Educational model. A deterministic in-memory placement model, not a database — real mechanics, simplified scale. Every number below is computed, not illustrated.

Partitioned: 1 machine, 12 rows. Sharded: 3 machines, 12 rows. Replicated: 3 machines, 36 rows. Everything else follows from those two numbers.

Arrangement one

Partitioning — chunks of one table, one machine

Three region partitions (p_us, p_eu, p_ap) inside a single database. Run a query that carries the partition key, then one that does not.

Pick a query above.

Arrangement two

Sharding — a hash decides which machine owns each row

Three machines, each owning the rows its hash assigns. A lookup by id touches one shard; a join across shards or a query without the key fans out. Then add a shard and count what moves.

Pick an operation above.

Arrangement three

Replication — every node holds every row

Nothing is split: the primary and two replicas each store all 12 rows (36 stored). Write to the primary, then read a replica before the stream catches up.
